# مرحله ۰۲ — پیشرفت زیرساخت

## آنچه انجام شده

اسکلت پروژه Kotlin/Compose و مدل اولیه Room برای صف فرمان‌های محلی اضافه شده است. شناسه فرمان کلید اصلی است و جایگزینی تصادفی آن رد می‌شود؛ رکوردها به حساب و مجموعه محدودند. Rules اولیه Firestore و Storage عمداً همه دسترسی‌ها را رد می‌کنند تا پیش از طراحی و آزمون کنترل دسترسی، داده‌ای ناخواسته منتشر نشود. صفحه فعلی فقط وضعیت توسعه را اعلام می‌کند و داشبورد یا عملکرد عملیاتی نیست.

## محدودیت‌ها و آزمون

در محیط فعلی Java، Android SDK، Gradle و Firebase CLI نصب نیستند؛ دسترسی به مخازن Google/Gradle نیز در این محیط فراهم نیست. بنابراین build، آزمون Room، Firebase Emulator و آزمون روی دستگاه **اجرا نشده‌اند** و قابل کامپایل بودن هنوز تأیید نشده است. این مرحله کامل نیست. هنوز تنظیم Firebase، Auth، اتصال Room، موتور همگام‌سازی، WorkManager، migration، تست و مجوزهای نقش پیاده‌سازی نشده‌اند. Rules فعلی نباید به‌عنوان مجوز عملیاتی استفاده شوند و همه خواندن‌ها و نوشتن‌ها را مسدود می‌کنند.

## راه‌اندازی بعد از فراهم شدن ابزارها

JDK 17 و Android SDK 35 نصب کنید؛ سپس از ریشه `./gradlew :app:assembleDebug` را اجرا کنید. دریافت Gradle و وابستگی‌ها به دسترسی به مخازن مربوط نیاز دارد. برای Firebase CLI پس از نصب و تنظیم پروژه آزمایشی، `firebase emulators:start --project demo-alnasser` سرویس‌های تعریف‌شده را اجرا می‌کند. پیکربندی واقعی Firebase و اتصال SDK عمداً تا فراهم شدن پروژه مالک انجام نشده است؛ اطلاعات محرمانه نباید به مخزن اضافه شوند.

## ادامه

تأمین محیط build و آزمون، اجرای wrapper و تست Room و rules، طراحی قرارداد فرمان و پیاده‌سازی sync با کنترل حساب، تکرار و تعارض پیش از اعلام پایان مرحله ۰۲ لازم است. پاک‌سازی outbox در خروج از حساب باید با سیاست صریح برای داده ارسال‌نشده همراه باشد تا اطلاعات کاربر از دست نرود.

## پیشرفت بعدی: قرارداد اولیه فرمان

کد Cloud Function فراخوانی‌شونده `submitFuelRequest` در `firebase/functions` اضافه شد. این تابع فقط درخواست سوخت با وضعیت در انتظار ثبت می‌کند؛ سهمیه، مبلغ، تأیید و دفتر مالی را تغییر نمی‌دهد. ورودی دقیق شامل `tenantId`، `requestId` از نوع UUID نسخه ۴، `vehicleId`، `assignmentId`، `litersMl` صحیح مثبت و `occurredAtMillis` است. UID از Firebase Auth دریافت می‌شود، نه از payload. تابع در تراکنش Firestore فعال بودن مجموعه، راننده، خودرو و انتساب و تطابق آنها را بررسی می‌کند. درخواست تکراری با همان شناسه و محتوا نتیجه قبلی را برمی‌گرداند؛ استفاده مجدد از شناسه با محتوای متفاوت رد می‌شود. بررسی مجوز در درخواست تکراری نیز انجام می‌شود. Rules مستقیم همچنان بسته‌اند؛ این فرمان از Admin SDK استفاده می‌کند و کنترل دسترسی آن در خود تابع انجام می‌شود.

با Node 22، دستور `npm ci --prefix firebase/functions && npm test --prefix firebase/functions` آزمون‌های واحد را اجرا می‌کند. در اجرای فعلی ۷ آزمون با موفقیت گذشتند: ثبت و تکرار، تعارض شناسه، لغو مجوز، نقش/وضعیت، اعتبار ورودی، تطابق انتساب و یکسان بودن حروف شناسه. پایگاه داده در این آزمون‌ها یک نمونه حافظه‌ای است؛ این نتایج **اثبات رفتار هم‌زمانی Firestore، Rules یا اجرای emulator نیستند**. همچنین کلاینت اندروید هنوز به این تابع وصل نشده، احراز هویت و مدیریت انتساب پیاده‌سازی نشده و تابع deploy نشده است. برای بهره‌برداری ابتدا آزمون emulator و چنددستگاهی، محدودسازی سوءاستفاده، سیاست خطا، بازیابی و تأیید امنیتی لازم است.

## ادامه: صف محلی پایدار

مدل Room برای claim اتمیک فرمان‌ها در محدوده مجموعه و حساب گسترش یافت. فرمان در انتظار با lease و token اختصاصی در حال ارسال می‌شود؛ lease منقضی‌شده قابل بازیابی است و پاسخ فرستنده قدیمی با token اشتباه پذیرفته نمی‌شود. موفقیت، خطای قابل تلاش مجدد و خطای نهایی وضعیت جدا دارند و حذف عمومی فرمان‌ها حذف شد تا اطلاعات ارسال‌نشده به‌طور اتفاقی پاک نشوند. شناسه فرمان باید در فراخوانی سرور ثابت بماند؛ تکرار پس از از دست رفتن پاسخ با idempotency سرور کنترل می‌شود. lease بر مبنای ساعت دستگاه است، پس تغییر ساعت می‌تواند بازیابی را به تأخیر اندازد؛ پیش از استفاده عملیاتی باید سیاست بازنشانی امن پس از راه‌اندازی و آزمون آن تکمیل شود. خطا باید صرفاً کد غیرحساس باشد.

چهار آزمون instrumentation برای محدوده حساب، token، بازیابی lease، ترتیب، خطا و شناسه تکراری نوشته شد؛ **به علت نبود Android SDK/JDK اجرا نشده‌اند**. `exportSchema` فعال شده است و فایل schema هنگام نخستین build موفق تولید و باید همراه migrationهای آینده نسخه‌بندی شود. هنوز scheduler/Worker، اتصال Firebase و مدیریت چرخه حساب اجرا نشده‌اند؛ این صف به تنهایی همگام‌سازی عملیاتی نیست. حذف یا خروج از حساب نباید داده ارسال‌نشده را بی‌اطلاع کاربر حذف کند. پس از فراهم شدن محیط، `./gradlew :app:connectedDebugAndroidTest` آزمون‌ها را روی دستگاه یا emulator اجرا می‌کند.

## آماده‌سازی build و آزمون یکپارچه

Gradle Wrapper نسخه ۸.۱۰.۲ و workflow برای build اندروید، آزمون Room روی emulator، آزمون واحد Node و آزمون Firestore Emulator اضافه شد. آزمون یکپارچه شامل ثبت هم‌زمان یک شناسه با payload برابر یا متفاوت و بررسی بسته بودن Rules برای کلاینت است. برای اجرای محلی آن پس از نصب JDK و دسترسی به فایل‌های emulator:

```sh
npm ci --prefix firebase/functions
./firebase/functions/node_modules/.bin/firebase emulators:exec --project demo-alnasser --only firestore "npm run test:integration --prefix firebase/functions"
./gradlew :app:assembleDebug :app:connectedDebugAndroidTest
```

در این محیط `./gradlew --version` به دلیل نبود Java اجرا نشد و دانلود SDK/emulator از میزبان‌های Google نیز مجاز نیست. بنابراین نه workflow و نه آزمون‌های emulator یا build اندروید اجرا نشده‌اند؛ ساخت artifact در workflow نیز هنوز تأیید نشده است. در صورت موفقیت workflow، APK حاصل فقط اسکلت زیرساختی است، **نسخه قابل ارائه به مشتری نیست**. هفت آزمون واحد Node مجدداً موفق بودند و `node --check` فایل آزمون یکپارچه را پذیرفت. `npm audit --omit=dev` در زمان بررسی ۹ مورد moderate و هیچ مورد high یا critical گزارش نکرد؛ رفع و ارزیابی آنها پیش از انتشار لازم است.

## مسیر نسخه آزمایشی قابل ارائه

نسخه آزمایشی مشتری باید حداقل ورود واقعی و نقش‌های محدودشده، ثبت و مشاهده داده واقعی مجاز، وضعیت آفلاین و همگام‌سازی قابل آزمون، رابط فارسی و گزارش واضح محدودیت قابلیت‌های پیاده‌سازی‌نشده داشته باشد. پیش از تحویل، build موفق، تست امنیت و آزمون روی دستگاه واقعی لازم است. برای عملکرد مشترک واقعی، پروژه Firebase تحت مالکیت مجموعه، پیکربندی Auth، تأمین صورتحساب در صورت نیاز و داده‌های واقعی مجاز لازم‌اند. تا آن زمان هیچ APK یا داده ساختگی به‌عنوان محصول عملیاتی معرفی نمی‌شود. اولویت بعدی رفع موانع محیط build و اجرای تست‌ها، سپس تکمیل sync و هویت است؛ workflow فقط مسیر اجرای آزمون را آماده می‌کند و جایگزین نتیجه موفق نیست.
