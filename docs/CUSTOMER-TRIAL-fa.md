# راهنمای نسخه آزمایشی محدود مشتری

این نسخه برای بررسی اولیه ورود و ثبت خودرو است، نه راهکار کامل یا نسخه عملیاتی. قابلیت‌ها: تنظیم اطلاعات عمومی پروژه Firebase روی گوشی، ورود Email/Password، نمایش نقش تأییدشده، و برای مدیر نمایش زنده و ثبت پلاک، مدل و ظرفیت خودرو در Firestore مشترک. سایر نقش‌ها فقط ورود و نمایش نقش دارند. GPS، سوخت، سهمیه، مأموریت، حسابداری، ویرایش و حذف خودرو، جلوگیری از پلاک تکراری، ردیابی و گزارش‌ها پیاده‌سازی نشده‌اند. برای داده حساس یا فعالیت واقعی تجاری تا پایان آزمون امنیت، مدیریت کاربران، پشتیبان‌گیری و تأیید کامل از این نسخه استفاده نشود.

## آماده‌سازی Firebase متعلق به مجموعه

۱. یک پروژه آزمایشی جداگانه در Firebase بسازید، Firestore را ایجاد و ورود Email/Password را فعال کنید. برنامه Android با شناسه `com.alnasser.smartfleet` ثبت شود. از پیکربندی عمومی Firebase همان برنامه مقادیر Project ID، App ID و Web API Key را دریافت کنید. اینها رمز حساب سرویس نیستند. کلید خصوصی یا رمز مدیر را در برنامه پیکربندی یا مخزن قرار ندهید.
۲. Rules موجود در `firebase/firestore.rules` را فقط در پروژه آزمایشی بررسی و منتشر کنید. Rules همه دسترسی‌ها به‌جز پروفایل خود و مشاهده/ساخت خودرو برای مدیر فعال را رد می‌کنند. مجوزهای موجود پروژه را پیش از جایگزینی بررسی کنید. هیچ ادعایی درباره ایمنی پروژه‌ای با Rules متفاوت وجود ندارد.
۳. در Firebase Authentication کاربر ایمیل/رمز بسازید. UID کاربر را در کنسول ببینید. با دسترسی مدیریتی Firestore سند `tenants/<tenantId>` با فیلد `active` از نوع boolean برابر true و سند `tenants/<tenantId>/users/<uid>` با فیلدهای `active: true` و `role: "manager"` ایجاد کنید. tenantId فقط حروف انگلیسی، اعداد، خط تیره و زیرخط داشته باشد. نقش‌های `driver` و `accountant` نیز برای آزمون ورود پشتیبانی می‌شوند ولی مدیریت خودرو ندارند. این کار باید صرفاً توسط مدیر پروژه انجام شود؛ ابزار ثبت مدیر اولیه هنوز وجود ندارد.
۴. APK را نصب کنید. در صفحه تنظیم اتصال، سه مقدار عمومی Firebase را وارد کنید. صحت اتصال هنگام ورود بررسی می‌شود. سپس شناسه مجموعه، ایمیل و رمز حساب ساخته‌شده را وارد کنید. برای تغییر پروژه، داده برنامه را از تنظیمات Android پاک کنید؛ این کار داده محلی برنامه را نیز پاک می‌کند.
۵. مدیر می‌تواند خودروی جدید را ثبت کند؛ پس از تأیید سرور پیام موفقیت ظاهر می‌شود. روی گوشی دیگری با همان پروژه و حساب مجاز، خودروها باید در فهرست دیده شوند. ثبت آفلاین تا دریافت تأیید سرور در انتظار می‌ماند؛ نمایش محلی به‌معنای تأیید نیست. حذف یا ویرایش هنوز ممکن نیست.

## محدودیت‌های امنیتی و آزمون

این آزمون هنوز آماده بهره‌برداری نیست: ثبت خودرو مستقیم از کلاینت است و audit log و یکتایی پلاک ندارد؛ بازیابی نشست و لغو فوری دسترسی در همه حالات، صف آفلاین کامل، سیاست پاک‌سازی، مقیاس‌پذیری و تست چنددستگاهی واقعی تکمیل نشده است. پروژه آزمایشی را ایزوله و به داده غیرحساس محدود کنید. تأیید Rules در emulator جایگزین کنترل قواعد منتشرشده و آزمون روی دستگاه واقعی نیست.

## نتیجه ساخت این نسخه

در اجرای [42220804161](https://github.com/Companymeelano/Ranande/actions/runs/42220804161) روی commit `259b4ac`، ساخت debug APK، آزمون واحد و تست Auth/Firestore Emulator و آزمون‌های Room روی Android Emulator موفق شدند. آزمون عملی ورود و ثبت خودرو از خود APK با پروژه واقعی Firebase و آزمون چند گوشی انجام نشده است. artifact این اجرا نام تاریخی `android-debug-infrastructure-only` دارد، اما شامل APK همین نسخه محدود است. این APK با کلید debug امضا شده و برای انتشار عمومی یا استفاده عملیاتی مناسب نیست. نیاز به Android 8 یا جدیدتر دارد.
